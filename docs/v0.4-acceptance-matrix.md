# v0.4 需求与验收对应

批准范围见 [实施计划](cmdtyper-v0.4-plan.md)，最终运行结果见 [验收记录](validation_20260906.md)。

| 批准要求 | 实现与可核验依据 |
| --- | --- |
| 长流程逐条输入、逐步输出和上下文 | `data/sequences/workflows.toml` 的 40 个流程、216 步；`sequence_loader` 校验规范引用和顺序，`workflow_flow` 在各完整跟打入口提交当前步骤；`tests/workflow_steps.rs` 覆盖六类入口、长行、显示模式、首字符、最后完成和保存失败。 |
| 内容去重与历史兼容 | `catalog.rs` 拒绝规范目标重复，课程与场景引用 command_id；`command_aliases.toml` 保留 507 个迁移别名；`tests/aliases_migration.rs` 验证旧记录/掌握度/统计基线与失败恢复。 |
| 新增 ≥400 独立命令和 24 网络专题 | 489 条专题新命令有独立 ID 清单，严格排除旧 554 条命令的字面子串后仍有 488 条；专题和基础短题分别核算。见 `content_expansion_audit.json`、`content_sources_20260906.md` 和 `audit_practice_content.py`。 |
| 全部基础用法 1 教学 + 3 简单题 | 174 命令 L1、55 符号条目、52 系统章节共 281 组；引用不同题目且不重复教学题；`practice_loader` 校验来源覆盖；内容审计逐组记录核心能力及三题对应理由。 |
| 学习中心与共享进度 | 删除四个重复难度入口，保留原专题与 L1/L3/L5，增加基础用法和场景；专题详情 P 进入对应基础组，独立题按规范 ID 计数；`expansion_behavior` 与 `v03_behavior` 覆盖路由和计数。 |
| 20 个连贯实训与判断分支 | 20 案例、245 步、41 判断点，每例至少 8 步和 2 判断点；`scenario_training` 在真实 App 按键中逐一完成全部案例，验证每个错答回证据、正答推进、历史 ID 和复盘。 |
| 网站/运维案例内容可信 | Ubuntu、Compose、Nginx、FastAPI、PostgreSQL、Git 贯穿配置、健康、TLS、发布回滚和隔离恢复；场景 sources 与 `scenario_content_audit.md` 记录文档依据、环境边界和模拟状态。 |
| 全部完整跟打计入日历，其他训练排除 | 统一 `persist_record` 与 `active_typing_identity`，基础组按来源映射入口；`follow_typing_input`、`statistics_v2` 和 `expansion_behavior` 覆盖开始、部分保存、完成、入口归属及重复快照。 |
| 位置准确率、有效时长与跨日 | 位置错误不被退格清除、同位置误按去重，空闲最多 30 秒，输出阅读排除；输入时固定日期、跨日拆分；可控时间测试验证，时区切换由两个进程的实际记录验证。 |
| 逐字符滑动统计 | 最近 50 位置样本、10 样本门槛、各端 10% 缩尾后换算 CPM；排除首字符、暂停、长空闲和零间隔；跨日回访保留旧日快照。见 scorer/engine 单元测试、`statistics_v2` 及统计说明。 |
| 兼容、备份与落盘失败 | 先历史后缓存、稳定 session ID；原子发布迁移备份、旧统计基线保留、损坏历史拒绝覆写；注入中途复制失败、第二份备份失败、历史写失败及缓存失败验证。 |
| TUI 与打包验收 | TestBackend 渲染 40×10、80×24、120×36；真实 PTY 测试 release 与 Docker 的场景与四步工作流，所有练习历史隔离在临时目录。 |
| 本地、远程版本管理与推送 | 原始未提交工作独立提交为 `8a22401`；升级在 `feat/v0.4-training-upgrade`，发布标签 `v0.4.0`；本地工作区、intranet 工作区与 GitHub 对齐，以最终验收记录为准。 |

测试仅驱动教学应用、读取预置输出并写入隔离练习数据；不会执行训练内容中的运维命令。Bash 审计使用 `bash -n` 解析语法，不能替代逐组语义审查。
